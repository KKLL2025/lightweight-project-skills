# AI 协作项目目录标准

## 目录

- 三分区主结构
- 各分区细化
- 现有仓库兼容模式
- 根目录规则
- 输出与资产规则

## 三分区主结构

新建 AI 主导项目、混合资料项目，或用户明确要求主界面整洁分类时，采用下面的默认结构：

```text
project/
├── .git/
├── .gitignore
├── AGENTS.md                         # AI 自动发现的稳定规则和导航入口
├── README.md                         # 人类入口、启动方式和目录说明
├── 01-ai-runtime/                    # AI 运行所需文件
│   ├── instructions/                 # 项目专属指令；根 AGENTS.md 可链接到这里
│   ├── skills/                       # 项目专属技能，不存放全局安装技能副本
│   ├── prompts/                      # 可复用提示词和任务入口
│   ├── tools/                        # AI 使用的项目辅助工具和脚本
│   ├── config/                       # 项目级 AI/MCP/模型配置，不提交密钥
│   └── examples/                     # 少量有效用法示例
├── 02-project-control/               # 需求对齐、决策和项目管理文档
│   ├── alignment/                    # 目标、范围、非目标、需求、用户故事
│   ├── architecture/                 # 设计、接口、数据模型和重要 ADR
│   ├── planning/                     # 路线图、里程碑和执行任务
│   ├── continuity/
│   │   ├── PROJECT_INDEX.md          # 文档路由和权威关系
│   │   └── PROJECT_HANDOFF.md        # 当前阶段、风险和唯一下一步
│   ├── acceptance/                   # 验收账本、验收说明和缺口
│   ├── evidence/                     # 日志、截图、清单、哈希和测试证据
│   ├── research/                     # 调研、外部资料摘要和可追溯来源
│   ├── layout/
│   │   └── PROJECT_LAYOUT.json       # 目录角色、保护路径和输出边界
│   └── history/                      # 已关闭里程碑、旧计划和冷文档
└── 03-project-workspace/             # 项目实际文件
    ├── product/                      # 实际软件/产品仓库，保留框架原生结构
    │   ├── src-or-app/               # 示例名；实际名称服从框架
    │   ├── tests/                    # 可位于 product 内的框架约定位置
    │   ├── config/
    │   ├── scripts/
    │   └── docs/                     # 面向产品使用/维护者的工程文档
    ├── assets/
    │   ├── source/                   # 原始图片、音频、模型等受保护素材
    │   └── processed/                # 可再生成或已处理素材
    ├── data/
    │   ├── input/                    # 原始输入，默认保护
    │   ├── working/                  # 中间数据
    │   └── export/                   # 导出数据，不等于正式发布
    ├── outputs/
    │   ├── engineering/              # 本地工程检查通过的产物
    │   ├── candidates/               # 待外部或最终验收的候选
    │   └── releases/                 # 有完整发布证据的固定版本
    └── temp/                         # 缓存、临时日志和可再生成内容
```

这是一张角色地图，不是要求每个空目录都必须创建。只创建项目实际需要的分支；保留三大主入口及关键子目录命名的一致性。

## 各分区边界

| 分区 | 放入 | 不放入 |
|---|---|---|
| `01-ai-runtime` | 项目专属 AI 指令、技能、提示、工具与非敏感配置 | 产品源码、动态任务状态、验收结果、密钥 |
| `02-project-control` | 需求、设计、计划、交接、验收、证据、调研和历史 | 软件构建产物、用户原始素材、运行缓存 |
| `03-project-workspace` | 实际产品、工程资料、资产、数据、输出和临时文件 | 重复的需求真相、另一套项目状态账本 |

项目控制文件帮助 AI 开发，但不与 AI 运行组件混为一类。产品工程文档属于 `product/docs/`；决定“为什么做、做到什么程度”的文档属于 `02-project-control/`。

## 现有仓库兼容模式

当现有框架要求 `package.json`、`src/`、`apps/`、`Cargo.toml`、`go.mod` 或 CI 配置位于 Git 根目录时，不为了套用三分区而强行嵌套整个仓库。采用兼容模式：

```text
existing-repo/
├── AGENTS.md
├── README.md
├── <framework-native files and folders>
├── 01-ai-runtime/                    # 仅在有项目级 AI 资源时创建
├── 02-project-control/               # 对齐、计划、交接、验收、证据
├── outputs/                          # 若框架已有 dist/build，则沿用现有位置
└── assets-or-data/                   # 沿用并标注保护边界
```

兼容模式的目标是获得相同的角色边界，而不是获得完全相同的物理路径。迁移收益必须大于构建、CI、IDE、Git 和人员使用习惯的路径成本。

## 根目录规则

- 根目录保留 AI/人类发现入口、版本控制和框架强制入口。
- 新建普通文档、截图、安装包、导出文件、日志和草稿前先确定角色，不直接丢在根目录。
- `AGENTS.md` 指向项目索引、当前交接和布局契约；不要把完整项目手册复制到根文件。
- 同一动态事实只有一个维护者：任务状态、验收状态、当前交接和发布证据分别由各自权威文件维护。
- 未分类文件先放入明确标记的审查区或保持原位，不因追求整洁而删除。

## 输出与资产规则

- `engineering/` 仅表示本地工程检查边界，不表示用户验收。
- `candidates/` 保存待验收包并避免静默覆盖历史候选。
- `releases/` 中的每个正式版本必须能关联固定修订、清单、哈希和规定的外部验收。
- 原始资产与输入数据默认受保护；处理中间物和缓存必须可区分、可再生成或有清理依据。
- 文件夹名称表达角色，证据决定状态。
